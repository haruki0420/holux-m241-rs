3つのスキル（frontend-design / impeccable / unslop + baseline-ui / design-review / web-design-guidelines）を
通した設計記録。成果物は `PRODUCT.md` と `DESIGN.md`。

## 1. 方向（unslop の5行）

- **Product** — 2006 年製 GPS ロガーの日付を直し、記録した軌跡を地図に出す道具。
- **Character** — 落ち着いた、正確な、少しだけ警告的。
- **World** — 夜の机。片手には小さな画面の端末、もう片方には USB ケーブル。
  紙のマニュアルと、計測器の制御ソフト。
- **Moments** — 地図（唯一の明るい面）と、書き込みボタン（唯一の有彩色）。
- **Signature** — 左のタブが 8px ずつ階段状に出る親指インデックス。

| token | hex | ground 上 | panel 上 | 用途 |
|---|---|---|---|---|
| ground | `#14181A` | — | — | 地 |
| panel | `#1B2023` | — | — | 面 |
| rail | `#111416` | — | — | タブ列 |
| rule | `#2C3437` | 1.4 | 1.3 | 罫線 |
| ink | `#E8E6DF` | 14.3 | 13.2 | 本文 |
| mute | `#9AA0A0` | 6.7 | 6.2 | 補助 |
| danger | `#E3A008` | 7.9 | 7.3 | **予約** |

本文・補助すべて 4.5:1 以上（最小は err の 5.3）。rule は罫線なので対象外。
数値は WCAG の相対輝度式で実際に計算した値。初稿は概算で書いていて
0.3〜0.6 ずれていたので、計算し直して表を修正した。

型は 11 / 13 / 16 / 20 / 24（比 1.18 / 1.23 / 1.25 / 1.20）。
初稿の 13/14 は比 1.08 で役割が分かれないため 14 を捨て、本文を 16 に上げた。
暗地の明文字は 1 段太く、+0.01em のトラッキングで補正する。

## 4. egui に移せない web 指針と、その読み替え

`web-design-guidelines` の 40 項目のうち、ネイティブに効くのは次の 18。残りは DOM
固有なので対象外（ `<a>`、`aria-*`、`Intl.*`、`overscroll-behavior` など）。

| web の規則 | egui での実装 |
|---|---|
| icon-only ボタンに aria-label | アイコンだけのボタンを作らない。文字を併記する |
| form control に label | すべての `TextEdit` に行ラベルを付ける |
| キーボード操作 | 全操作を Tab / Enter / Esc で到達可能に |
| 可視フォーカス | 2px の `ink` 枠、内側 1px |
| `prefers-reduced-motion` | アプリ設定 + OS 設定の両方を読む |
| `transform`/`opacity` のみ | 幅・高さのアニメーションをしない |
| `transition: all` 禁止 | 対象を明示した 150ms のみ |
| `tabular-nums` | 数値は等幅フォント + 右揃え |
| `…` を使う | ローディングは `読み込み中…` |
| 破壊的操作に確認 | `WRITE` の入力。モーダルではなく同画面内 |
| エラーは発生源の隣 | 失敗は該当ステップの直下に出す |
| 空状態に次の一手 | 「まだログがありません」+ ダウンロード導線 |
| 長文の切り詰め | パスと sha256 は中省略、ホバーで全文 |
| 画像に width/height | サムネイルはアスペクト比を固定して CLS を防ぐ |
| 大リストの仮想化 | ログ点は全描画せず、表示範囲だけ間引く |
| `autoFocus` を慎重に | 起動時にどこにもフォーカスを奪わない |
| コピーは能動態 | 「ファームを吸い出す」 |
| エラーに次の一手 | 端末の言葉 → 我々のヒント、の順 |

`baseline-ui` は Tailwind / React 前提なので、**原則だけ**を採る:
破壊的操作は保護された確認、空状態は次の一手を1つ、アクセントは 1 画面 1 色、
グラデーションとグローは使わない、アニメーションは要求されるまで足さない。

## 5. design-review の実施計画

実行可能になった時点の手順を DESIGN.md の §8 に固定した。

4. a review document beside this one に Must / Should / Could で記録

## 6. 機械的に検証する3点（CI に入れる）

```rust
// 1. danger は破壊的モジュールの外で使われない
// 2. 角丸は RADIUS 定数以外を使わない
// 3. 状態色は必ず文字ラベルと隣接する
```

あり、hover / focus / selection のどれでもないことを assert する。
