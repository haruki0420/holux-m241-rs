# デザイン設計 — holux-m241-rs

設計判断の記録。トークン表・画面仕様の正本は [`DESIGN.md`](../../DESIGN.md)、製品方針は [`PRODUCT.md`](../../PRODUCT.md)。

## 1. 方向と却下案

- **方向**: 2006 年製 GPS ロガーを夜の机で修理・計測する道具。地図を唯一の明るい面、書き込みボタンを唯一の有彩色（amber）とし、左レールは 8px ずつ階段状に出る親指インデックスとする。
- **却下案**: 生成り紙＋テラコッタ＋セリフ（雑誌調）、黒地＋蛍光アクセント（危険色を装飾に消費）、SaaS カードキット（表と行の階層を壊す）、ライトテーマ（夜の机に不適）。

## 2. トークンと判断根拠

色・コントラスト実測（全テキスト ≥ 4.5:1、最小 `err` 5.3:1）・型スケール（11/13/16/20/24；初稿の 13/14 は比 1.08 のため 14 を廃止）は `DESIGN.md` §3 を正本とする。

## 3. egui への読み替え（`web-design-guidelines` / `baseline-ui`）

Web 固有項目（DOM/`aria-*`/`Intl.*`）を除き、ネイティブに効く 18 原則を採用:
- テキスト併記（アイコン単独ボタン不可）、全 `TextEdit` に行ラベル、Tab/Enter/Esc 操作、2px `ink` フォーカス輪、`prefers-reduced-motion`＋アプリ設定、150ms 明示遷移（幅・高さのアニメなし）、等幅右揃え数値、ローディングは `…`、破壊的操作は同画面内 `WRITE` 入力、エラーは発生源直下に「端末の言葉→ヒント」、空状態に次の一手、長文中省略＋ホバー全文、アスペクト比固定、大リスト間引き、起動時フォーカス奪取禁止、能動態コピー。
- `baseline-ui` 原則: 保護された破壊確認、アクセント 1 色、グラデーション/グロー禁止。

## 4. レビュー手順と CI 機械検査

UI 変更時は `m241-gui --screenshot`（1280×800 / 1024×640）で PNG を出力し、`DESIGN.md` §8 に沿って点検して [`10-review-log.md`](10-review-log.md) に記録する。CI の `tools/check_design.py` が (1) `tokens::DANGER` は `screens::firmware` のみ、(2) 角丸は `theme::RADIUS` のみ、(3) 状態色とラベル併記、の 3 点を機械検証する。

## 8. 軌跡の 10 色パレットと始点・終点マーカー（`07-eztour-spec.ja.md` §5 の読み替え）

- **10 色パレット**: 線幅 5 pt・不透明度 0.7（`data`）をそのまま採り、`theme::TRACK_PALETTE`（10 色）は線ではなく点の塗りに適用した（`DESIGN.md` §3 の単色 `data` 規則との整合、および単一ログでの記録順表現のため）。パレット 9 色を WCAG テキスト検証に含めるかは未決。
- **8.1 始点・終点マーカー**: 画像アイコンの代わりに `ink` の中抜きリング（始点 1.5 倍、終点 2.5 倍、`metric::POINT_DOT` 基準；POI 2 倍・選択 3 倍と区別）で描き、`crates/m241-gui/tests/render.rs` で固定している。`DESIGN.md` への昇格は未決。
