## 1. 何を作っているか

**Holux M-241**（MediaTek MT3318 の GPS ロガー、2006 年製）の
**GPS ウィークナンバーロールオーバー**を直すツール。

2006 年製ファームが GPS エポック定数 `315964800` を直書きしていて、
2019-04-06 の第 2 ロールオーバーを考慮していない。記録される日時が
**19.6 年（7168 日）過去**になる。

`0x402F4` の 4 バイトを `935280000` に書き換える（**実際に変わるのは 3 バイト**）。

- リポジトリ: <https://github.com/haruki0420/holux-m241-rs>（公開、MIT）
- Python 版（v1、実機で動く唯一の実装）: 別リポジトリ `holux-m241-wnro-toolkit`
- Nekoba 版（別実装）: <https://github.com/NekobaTechnology/holux-m241-wnro-fix>

| コマンド | 内容 | 危険度 |
|---|---|---|
| `0xD3` | レンジ記録。成功 `5A 00` 2 バイト / 失敗 `A5` 1 バイト | 中 |
| `0xD5` | **書く前にセクタ単位で消去**。パケット → `0x69`、完了で `5A 5A` | **高** |

バイトを送る必要があるか。**v1 は送らずに実機で成功している**ので、
v1 と同じ方式で実装し、実機で確定させる。

**安全ゲート 3 つ**（`docs/reference/02-cli.md` の `fw flash`）:

1. イメージがプロファイルに一致する、**または**バックアップとの差分が
   パッチ offset 内に収まる
2. イメージが DA の報告するフラッシュサイズに収まる
3. 利用者が `WRITE` と入力する

### 3.5 実機検証

**まだ一度も実機で動かしていない。** 最初にやるのは**読み取りのみ**
（危険ゼロ）:

```bash
m241 device ports
m241 device info          # $PMTK705 のパースが実機で合うか
m241 fw dump -o backup/   # 読み取りのみ。2回読んで比較
m241 fw patch --dry-run   # 吸い出したイメージがプロファイルに一致するか
```

**この 1 セッションで確定するもの**:
- BootROM 同期が今のコードで通るか
- ダンプの SHA-256 がプロファイルに一致するか
- `0xA2` / `0xAF` のバイト順変換が正しいか
- 実機の応答速度（タイムアウト値の妥当性）
- **シミュレータの仮定がどこまで正しいか**

書き込みの実機検証はその次。**バックアップから復旧できることも確認する。**

## 4. ブロッカーと注意点

### 4.1 実機が無い

これが最大の制約。**このリポジトリのコードは一度も実機で動いていない。**
すべて `FakeDevice`（シミュレータ）と合成データに対する検証。

### 4.2 シミュレータは正しさの証明ではない

**重要**: シミュレータはクライアントと同じ関数（`swap_pairs` など）を
共有しているので、バイト順の誤りを検出できない（循環参照）。

シミュレータの役割は「リファクタで壊したときに気づく回帰テスト」。
正しさの担保は「逆解析の citation」+「実機確認」+「レビュー」の 3 つ。

### 4.3 未確定項目（`01-da-protocol.md` §7）

| # | 内容 | 実装への影響 |
|---|---|---|
| 1 | `0xD5` の最終 2 個の `0x5A` の間 | **ブロッカー**。v1 方式で回避 |
| 2 | `0xD1` の目的 | 実装しない |
| 3 | `0xDA` の half-word の出所 | 実装しない |
| 4 | `0xD6` の実機ページ長 | 実装しない |
| 5 | レンジ単位チェックサム | 無いと判断 |
| 6 | リージョン選択 | `0x49` 固定 |
| 7 | `0xD5` リトライの `0x69` 重複 | 実装時に考慮 |

### 4.4 個人データをコミットしない

公開リポジトリ。`AGENTS.md` §9（旧 §9、今は §12）に規約あり。

- 実座標禁止。`35.6812360, 139.7671250`（東京駅）か no-fix の `8960.0000,N,00000.0000,E` のみ
- ローカルパス禁止
- 実機のシリアルポート列挙禁止（`COM3` の例は OK）
- ベンダーバイナリ（`DA_v3.8.4.bin`、ファーム、DLL、EXE、ZIP）は絶対にコミットしない

`docs/dev/12-progress-summary.md` と本文書は個人データゼロを確認済み。

## 5. レビュー体制（必ず守る）

`AGENTS.md` §8 に **三段構成**が明文化されている。

1. **発見** — レビュアーが `file:line` で指摘だけ書く。**直さない**
2. **修正** — **別の**エージェントが直す。指摘が誤りなら直さず異論を述べる
3. **検証** — **三人目**が指摘・差分・テストで確認。**修正者の説明は読まない**

**5/5 ゲートは「壊れていない」証明であって「指摘が解消した」証明ではない。**
検証列が埋まるまでマージしない。

`AGENTS.md` §9 に**失敗の記録 7 項目**がある。必読。特に:

- 検証を飛ばして 4 本マージした
- レビューした本人が修正を書こうとした
- 差分を読んで「妥当」と判断した（発見と受入を兼ねた）
- エージェントの失敗を成果物の失敗と誤認した
