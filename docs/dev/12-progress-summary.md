## 1. 何を作っているか

**Holux M-241**（MediaTek MT3318 の GPS ロガー、2006 年製）の
**GPS ウィークナンバーロールオーバー**を直すツール。Rust 3 クレート + GUI。

2006 年製ファームが GPS エポック定数 `315964800` を直書きしていて、
2019-04-06 の第 2 ロールオーバーを考慮していない。記録される日時が
**19.6 年（7168 日）過去**になる。`0x402F4` の 4 バイトを `935280000` に
書き換える（実際に変わるのは 3 バイト）。

現状は **Python 版（v1）が実機で動く唯一の実装**。このリポジトリは Rust で
作り直している途中。

## 4. 完成しているもの

### 4.1 逆解析（今日の最大の成果）

`docs/reference/01-da-protocol.md` — **723 行、命令アドレスつき**

`DA_v3.8.4.bin`（14,896 バイト、ARM、ロードアドレス `0x00100800`）を
逆アセンブルして、Download Agent のコマンド体系を確定させた。

**6 つの問いすべてに回答済み:**

| 問い | 答え |
|---|---|
| `0xD3` の status byte | 常に `0x00`。**失敗時は送られない**。失敗応答は `0xA5` 1 バイトのみ |
| range はセクタかバイトか | バイト単位、両端含む。start 偶数、end 奇数必須 |
| 最大パケット長 | プロトコル上の上限なし。制約はリング空きのみ |
| チェックサム検証 | する。パケット単位 + 転送後読み戻しの二重 |
| `0xD2` / `0xD9` の引数 | `0xD2` は index + echo count + `0xC0`/`0x5A` ハンドシェイク。`0xD9` は**引数も応答もなし** |
| 保護領域への書き込み | `0xD3` が単独 `0xA5` で拒否、既存レンジは保持。実消去は `0xD5` |

**過去の記述の訂正 10 件**（既存文書と Python 実装が間違っていた）:

| 訂正前 | 訂正後 |
|---|---|
| リトルエンディアン | **全体がビッグエンディアン** |
| `0xD3` が消去する | **消去しない**。消去は `0xD5` がセクタ単位で書く直前 |
| `0xD3` は常に 2 バイト応答 | 成功 2 バイト / 失敗 1 バイト（**可変長**） |
| `0xD4` はチェックサム | 消去 + 進捗フレーム `0x04 nn` |
| `0xD6` は引数 2 つ | 3 つ |
| `0xD8` は 1 バイト応答 | 3 バイト |
| `0xD3` の end は長さ | **アドレス**（間違えると次の `0xD5` で全部消える） |
| `0xD2` の第 2 引数 | echo count + ハンドシェイク必須 |
| バナー中央 4 つはジオメトリ | メーカー ID `0x00C2` / デバイス ID `0x22BA` |
| リージョン `+0x0C` はセクタ数 | 記述子カウント + メーカー ID |

**未確定 7 項目**（推測で埋めず明記）: `0xD5` の最終 2 個の `0x5A` の間、
`0xD1` の目的、`0xDA` の half-word の出所、`0xD6` の実機ページ長、
レンジ単位チェックサムの有無、リージョン選択、`0xD5` リトライの `0x69` 重複。

**危険点 9 項目**（§8）: `0xD5` のセクタ消去、`0xD3` の可変長応答、
失敗時のレンジ保持、`0xD9` の無応答、`0xD4` の破壊性、`0xD7`/`0xD8` が
フラッシュプリミティブでないこと、チェックサムのバイト順、`end` はアドレス、
最終パケットが短いのは正常。

### 4.3 CLI（`feat/cli-wire2`、未マージ）

**8 コマンド実装済み、テスト 84 件追加**:

`device ports` / `device info` / `fw dump` / `fw patch` / `log download` /
`log read` / `log info` / `nmea repair`

重要な実装:
- `fw dump` は **2 回読み + SHA-256 比較**、間に電源再投入プロンプト、不一致なら exit 4 でファイルを残さない
- `fw patch` は**ポートを一切開かない**（grep で確認済み）
- `log download` は**失敗しても必ずロギング再開**
- `nmea repair` は日付フィールドのみ書き換え + チェックサム再計算

## 6. レビュー体制

`AGENTS.md` §8 に **三段構成**を明文化:

1. **発見** — レビュアーが `file:line` で指摘だけ書く
2. **修正** — **別の**エージェントが直す。指摘が誤りなら直さず異論を述べる
3. **検証** — **三人目**が指摘・差分・テストで確認。**修正者の説明は読まない**

`AGENTS.md` §9 に**失敗の記録 7 項目**を残している。実際に起きたミスだけ:

- 検証を飛ばして 4 本マージした（5/5 は「壊れていない」証明で「指摘が解消した」証明ではない）
- レビューした本人が修正を書こうとした
- 差分を読んで「妥当」と判断した（発見と受入を一人で兼ねた）
- エージェントの失敗を成果物の失敗と誤認した（1389 行を捨てかけ）
- `.cargo-home` のシンボリックリンクが全 worktree で untracked になった
- ワークツリー 10 本でディスク 85%
- 同じ未完成作業が 2 回報告された
